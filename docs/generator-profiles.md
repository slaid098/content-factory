# Профили генератора: рецепт производства

`profile.yaml` описывает не только параметры рендера, но и то, каким
способом и с какими проверками производится контент. Блок `production`
необязателен; его отсутствие означает прежний единственный шаг Vast.

```yaml
production:
  - producer: vast
    type: video
    qa: [media, clef]
```

Поля шага:

- `producer` — имя зарегистрированного producer'а, обязательно.
- `type` — тип контента, по умолчанию `video`; producer должен его
  поддерживать (`vast` производит только видео).
- `qa` — упорядоченный список именованных проверок; по умолчанию
  `[media, clef]`. Пустой список запрещён: рецепт не может отключать QA
  целиком.

Без блока `production` профиль получает ровно текущее поведение:

```yaml
production:
  - producer: vast
    type: video
    qa: [media, clef]
```

## Проверки при загрузке

`load_profile` проверяет рецепт до аренды сервера и бросает `ProfileError`,
если:

- `production` пуст или задан не списком;
- шаг не словарь или в нём нет `producer`;
- producer или QA не зарегистрированы (в сообщении есть имя профиля и
  список допустимых значений);
- producer повторяется в рецепте, QA повторяется в шаге;
- `type` неизвестен или не поддерживается producer'ом.

Старые `profile.yaml` без блока не мигрируются.

## Producers

Реестр — `services/production/registry.py`: `register(name, factory)`,
`resolve(name)`, `available()`. Тесты используют отдельный `Registry` или
`reset()`, поэтому инъекция не протекает в другие тесты.

Первый producer — `vast`: адаптер над существующим
`services.generator.generate_batch`, `supported_types = {video}`. Он не
меняет результат и не знает про выдачу и сток; публикация остаётся в общем
хвосте генератора.

`flows/generate_batch/flow.py` загружает профили, берёт producer'ов из
рецепта и вызывает `produce` для каждого шага. Имя flow, параметры
`profiles/count/dry_run` и строка исхода сохраняются.

## Партии и `run_id`

Если у всех профилей рецепт — один шаг `vast/video`, flow вызывает
`generate_batch` один раз со всеми профилями: `count` и планы проверяются до
аренды, а все профили входят в один `run_id`. Неоднородные рецепты
выполняются по шагам, каждый со своим `run_id`; все они перечисляются в
строке исхода (`run=... run=...`), ни одна партия не теряется. `count`
проверяется до первого producer'а.

## QA

Реестр — `services/production/qa.py`. Список `qa` шага **добавляет**
именованные проверки, но не снимает обязательные:

- `media` (`final`) — `qa.check_video`: mp4 читается, содержит видео,
  ожидаемую аудиодорожку и длительность в допуске. Проверка выполняется
  всегда перед публикацией в сток, даже если шаг объявляет только `clef`;
- `clef` (`source`) — проверка кадров исходника до наложения текста.
  Выполняется всегда при `GENERATOR_SAFETY_ENABLED=true`, даже если шаг
  объявляет только `media`; при `GENERATOR_SAFETY_ENABLED=false` Clef, как
  и раньше, не вызывается.

Дополнительные объявленные проверки выполняются после обязательных, в
порядке списка `qa`, без повторения `media` и `clef`. Если проверка не
прошла, ролик получает `failed`, а публикации в сток нет. Рецепт не может
ослабить безопасность данными профиля.

## `run.json`

Отчёт фиксирует рецепт:

- `production` — шаги профиля (`producer`, `type`, `qa`);
- у каждого item — `producer`, `type` и `qa` выполненного шага.

При `dry_run` producer не вызывается: строится план, рецепт проверяется и
попадает в `run.json`.

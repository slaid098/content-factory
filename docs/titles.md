# Названия видео

Отдельный Prefect flow `titles` назначает осмысленные названия стоковым видео
по трём кадрам через DeepSeek V4.1 Flash. Названия уникальны в рамках всей
сети, пишутся на языке видео и хранятся в операционной SQLite-базе по
SHA-256 файла, поэтому переживают выдачу и не зависят от строки `videos`.

Flow не меняет поставщика, фильтры, критерии отбора и существующую выдачу.
Пока выдача строит sidecar по-старому (#40 переведёт её на эту таблицу).

## Таблица

```sql
CREATE TABLE IF NOT EXISTS titles (
    sha256 TEXT PRIMARY KEY,
    title TEXT NOT NULL,
    norm TEXT NOT NULL UNIQUE,
    created_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_titles_created_at ON titles(created_at DESC);
```

| Поле | Значение |
|---|---|
| `sha256` | SHA-256 файла `content/<lang>/<sha256>.mp4` |
| `title` | Название после схлопывания пробелов, 15–70 символов |
| `norm` | Нормализованный ключ названия; уникален глобально, не по языку |
| `created_at` | ISO 8601 момент сохранения |

`norm` получается из `title` приведением к нижнему регистру, заменой `ё` на
`е` и удалением пунктуации, эмодзи и подчёркиваний. Два названия, которые
отличаются только форматированием, считаются одним и тем же.

## Flow

```
src/content_factory/flows/titles/flow.py:titles
```

Один проход:

1. сканирует `content/<lang>/*.mp4`, где `<lang>` — ровно две строчные
   латинские буквы; язык берётся из имени каталога, а не из `videos`;
2. читает названия всех найденных хэшей одним запросом пачками по 500;
3. пропускает файлы, у которых уже есть непустое название;
4. для остальных берёт описание, поисковый запрос и длительность из
   `videos`/`downloads`; осиротевший mp4 обрабатывается с пустым описанием и
   `duration=None`;
5. извлекает кадры на 10 %, 50 % и 90 % длительности (без длительности —
   1, 3 и 6 секунд), пустые и совпавшие кадры отбрасывает;
6. просит три варианта названия, проверяет их и сохраняет первый свободный;
7. при коллизии `norm` переходит к следующему варианту, а если заняты или
   невалидны все — оставляет файл без названия до следующего запуска.

Ошибка одного файла логируется и увеличивает счётчик пропусков; остальные
файлы обрабатываются. Ошибки SQLite не глотаются и валят flow. Одинаковый
`norm` не может быть сохранён дважды, поэтому два одновременных запуска не
создают дублей.

Название не может быть пустым, равным `Видео`/`Video`, содержать слова
`видео`, `video`, `ролик`, `shorts`, `клип`, `clip`, хэштеги, ссылки,
`@`-упоминания, кавычки или эмодзи. Для `ru`, `uk`, `kk`, `bg`, `sr`, `mk`,
`be` нужна хотя бы одна кириллическая буква, для остальных языков — хотя бы
одна латинская и ни одной кириллической.

## Расписание

Deployment `titles` запускается каждые 10 минут по UTC с
`concurrency_limit: 1`. Воркер держит два слота (`--limit 2`), чтобы долгий
`stock_topup` не блокировал тики названий; каждый deployment при этом
выполняет не больше одного run.

```yaml
- name: titles
  entrypoint: src/content_factory/flows/titles/flow.py:titles
  work_pool:
    name: content-factory
  schedules:
    - slug: every-10-minutes
      cron: "*/10 * * * *"
      timezone: UTC
      active: true
  concurrency_limit: 1
```

Повторный запуск идемпотентен: уже названные файлы не трогаются, оставшиеся
берутся снова.

## Fallback

Запасного названия нет. Если API недоступен после трёх попыток, кадры не
извлеклись, все варианты невалидны или заняты, файл остаётся без строки в
`titles` и попадает в следующий запуск. `Видео`, `Video` и пустая строка в
таблицу не пишутся: пока выдача строит sidecar по-старому, её fallback живёт
только в коде выдачи и в `titles` не попадает.

## Настройки

Все значения читаются только из окружения. Compose подхватывает `.env` из
корня проекта.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TITLES_API_URL` | `https://ollama.com/v1` | база OpenAI-совместимого API; только `http`/`https`, без пробелов и завершающего `/` |
| `TITLES_API_KEY` | — | ключ API; пусто — flow возвращает `disabled` и не падает |
| `TITLES_MODEL` | `deepseek-v4.1-flash` | модель |
| `TITLES_TIMEOUT_SECONDS` | `60` | таймаут HTTP-запроса, 5–300 |
| `TITLES_REASONING_EFFORT` | `none` | `none`, `low`, `high` или `max` |

Ключ не попадает в repr настроек, логи, ошибки и git. В логах нет также
заголовка `Authorization`, промпта и тела ответа API.

## Первый запуск

1. Добавьте `TITLES_API_KEY` в `.env` на сервере (файл не коммитится).
2. Задеплойте `main`: `prefect.yaml` содержит оба deployment, а
   `prefect deploy --all` подхватывает их без ручных шагов.
3. Дождитесь ближайшего тика `titles` или запустите его вручную:

   ```bash
   sudo docker compose run --rm --no-deps worker \
     prefect deployment run titles/titles
   ```

4. Проверьте итог в логах (`titled=… skipped=…`) и строки в базе:

   ```bash
   sudo docker compose exec api \
     python -c "import sqlite3; print(sqlite3.connect('/app/app_data/db/db.sqlite3').execute('select count(*) from titles').fetchone())"
   ```

Первый прогон обрабатывает весь текущий сток; следующие берут только новые
файлы. Файл, оставшийся без названия, повторяется на каждом тике, пока
варианты не закончатся или API не ответит.

# Исходники профиля и producer `unique`

Пул исходников позволяет собирать профильные ролики без Vast.ai и ComfyUI:
готовый mp4 уникализируется карточкой, текстом и музыкой профиля и
публикуется в тот же профильный сток, что и ролик из Vast. General и Profile
не смешиваются: исходник принадлежит ровно одному языку и профилю, а
результат попадает в `content/<niche>/<language>/`.

## Раскладка

```
app_data/sources/<language>/<profile_slug>/<name>.mp4
```

`profile_slug` — имя профиля с заменой `/` на `_`, как в `generated/` и стоке:
`dating/profile_1` → `dating_profile_1`. Вложенные папки внутри профиля
допускаются, импорт обходит дерево рекурсивно. Файлы не копируются и не
меняются; в базе хранится путь относительно `app_data`, например
`sources/ru/dating_profile_1/a.mp4`.

Профиль ищется по `profile.yaml` в `app_data/profiles`; язык папки должен
совпадать с полем `language` профиля, иначе файл пропускается с
предупреждением.

## Импорт

```bash
python -m content_factory.services.sources.main --sources app_data/sources
```

Без `--sources` берётся `<CONTENT_FACTORY_DATA_DIR>/sources`. Команда
идемпотентна и печатает счётчики по языкам и профилям:

- `добавлено` — новый исходник;
- `обновлено` — тот же путь с новым sha256 (новый исходник, история
  использования сброшена);
- `вернулось` — файл, ранее помеченный `missing_at`, снова на месте;
- `без изменений` — тот же путь и sha256;
- `дубликатов` — тот же sha256 у другого файла профиля, запись не создаётся;
- `пропало` — строка есть, файла на диске нет; ставится `missing_at`.

Импорт считает sha256, размер и длительность через `ffprobe`
(`media.probe`). Файл без видео-потока, битый или нечитаемый пропускается с
предупреждением и в пул не попадает. Повторный запуск не создаёт дублей;
вернувшийся файл снимает `missing_at`, а новый хеш по тому же пути сбрасывает
`used_at` и `use_count`.

Импорт пишет `source_items` и `source_cursors` в ту базу, которую выбирает
`CONTENT_FACTORY_DATABASE_URL` (SQLite или PostgreSQL). Это отдельный шаг от
`db.import_sqlite`: при переключении на PostgreSQL исходники нужно
импортировать этой командой заново, потому что файлы уже лежат на диске.

## Курсор

`source_cursors(language, profile_id)` хранит `last_source_id` — последний
успешно опубликованный исходник. Следующая партия берёт строки с `id >
last_source_id`, затем продолжает с начала. `missing_at IS NOT NULL`
пропускается. Внутри одной партии исходник не повторяется.

Курсор двигает только успешная публикация: `source_items.used_at` и
`use_count` обновляются вместе с курсором в одной транзакции. Если item
упал, его исходник не сжигается, а курсор остаётся на последнем успешном
(при единственном item — на прежнем месте).

## Рецепт

```yaml
production:
  - producer: unique
    type: video
    qa: [media, clef]
```

`unique` поддерживает только `video`. На каждый исходник:

1. `clef` проверяет кадры исходника до карточки (если проверка объявлена и
   `GENERATOR_SAFETY_ENABLED=true`);
2. текстовая модель генерирует карточку профиля;
3. карточка и музыка профиля накладываются на исходник;
4. `media` и остальные final-проверки проверяют готовый mp4;
5. `publish_stock` публикует файл в `content/<niche>/<language>/`.

Vast.ai не арендуется, ComfyUI не вызывается. Сеть — текстовая модель и
объявленная проверка `clef`. В `run.json` у item появляются `source_path`,
`source_sha256` и длительность исходника.

## Пустой пул и `dry_run`

Если доступных исходников меньше `count`, producer падает до первого рендера
и публикации: `в пуле профиля … доступно N исходников, нужно M`. Ничего не
сжигается, партия не начинается. Пустой или отсутствующий пул даёт понятную
ошибку с подсказкой про импорт.

`dry_run` для `unique` читает следующие исходники и пишет их путь, sha256 и
длительность в `run.json`, но не двигает курсор, не зовёт LLM и не трогает
сеть. Для `vast` и `card` план прежний: looks/seeds/frames и имена файлов.

## Откат

Схема миграции только вперёд, обратной миграции нет. Чтобы убрать пул,
остановите API и воркер и удалите строки:

```sql
DELETE FROM source_cursors;
DELETE FROM source_items;
```

Файлы в `app_data/sources` при этом не трогаются: их можно импортировать
заново. Сток и `generated/` откат не затрагивает.

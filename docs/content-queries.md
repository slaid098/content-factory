# Поисковые запросы

HTTP-контракт для полного списка поисковых запросов по языку и добавления
нового запроса без SSH. Файл `app_data/queries/<language>.txt` остаётся
источником правды: следующий прогон производства читает его заново, поэтому
перезапуск не нужен.

## Авторизация

Оба маршрута требуют тот же Bearer-токен, что и остальные `/api/v1/content/*`:

```
Authorization: Bearer <CONTENT_FACTORY_DELIVERY_TOKEN>
```

- токен не задан в окружении — `503`, выдача выключена;
- токен неверный или заголовка нет — `401`;
- токен и содержимое файла запросов не логируются.

Язык должен быть описан в `languages` runtime-конфига
`app_data/config/config.yaml`. Флаг `enabled` не важен: список и добавление
работают и для выключенного языка. Неизвестный язык или код не по regex
`^[a-z]{2,3}$` — `422`.

## Список запросов

```
GET /api/v1/content/queries?language=ru
```

Ответ:

```json
{
  "language": "ru",
  "queries": [
    {"query": "курятник", "count": 3, "in_file": true},
    {"query": "заправка", "count": 0, "in_file": true},
    {"query": "старый запрос", "count": 1, "in_file": false}
  ],
  "unclassified": 0,
  "total": 4
}
```

| Поле | Значение |
|---|---|
| `queries[].query` | Строка запроса без комментариев и пустых строк |
| `queries[].count` | Остаток `.mp4` этого языка, найденных запросом |
| `queries[].in_file` | Запрос есть в `<language>.txt` |
| `unclassified` | Файлы без строки в `downloads`/`videos` или с пустым `videos.query` |
| `total` | Весь остаток языка: сумма `count` плюс `unclassified` |

Сначала идут все строки файла в исходном порядке, включая запросы с нулевым
остатком. Затем — запросы из `videos.query` этого языка, которых нет в файле:
они получают `in_file: false`, а `count` считается по тому же остатку.
`unclassified` и `count` считаются так же, как в
`GET /api/v1/content/topics`.

Граничные случаи:

- файла нет — `queries` содержит только запросы из БД с `in_file: false`;
- нет остатка — все `count` равны нулю, `total` равен `unclassified`;
- БД нет или она не читается — все `count = 0`, `unclassified = 0`,
  `total = 0`, список файла всё равно отдаётся;
- в файле есть комментарии и пустые строки — в ответ они не попадают.

## Добавление запроса

```
POST /api/v1/content/queries
Content-Type: application/json

{"language": "ru", "query": "новый запрос"}
```

Ответ `200`:

```json
{"language": "ru", "query": "новый запрос", "created": true}
```

Повтор существующего запроса возвращает `created: false` и не меняет файл:

```json
{"language": "ru", "query": "новый запрос", "created": false}
```

Правила запроса:

- пробелы и табы схлопываются в один пробел, края обрезаются;
- переводы строк и управляющие символы запрещены;
- после нормализации длина — от 1 до 200 символов;
- после нормализации запрос не должен начинаться с `#`: такая строка стала бы
  комментарием и не попала бы в список запросов;
- дубликат ищется по файлу без учёта регистра, поэтому `Курятник` и
  `  курятник  ` — один и тот же запрос.

Запрос дописывается в раздел `# Добавлено из интерфейса`:

```
# Список запросов
курятник

# Добавлено из интерфейса
новый запрос
```

- если раздела нет, он создаётся в конце файла;
- если раздел есть, запрос встаёт после последней непустой строки раздела,
  перед следующим заголовком-комментарием;
- комментарии и уже существующие строки не меняются и не переупорядочиваются;
- файла нет — он создаётся с заголовком раздела;
- файл без завершающего перевода строки — перевод строки добавляется перед
  новым разделом.

Запись атомарная: файл переписывается через временный файл в том же каталоге
и `os.replace`. Одновременные `POST` сериализуются in-process lock, поэтому в
файл попадает ровно одна строка. Кодировка — UTF-8; BOM, если он был,
сохраняется.

Добавление не запускает производство и не меняет `search.max_queries`.
Новый запрос подхватит следующий прогон; из-за перемешивания он может
попасть не в первый прогон.

## Ошибки

| Код | Когда |
|---|---|
| `401` | Нет заголовка или токен неверный |
| `422` | Язык не по regex, языка нет в конфиге, пустой/длинный запрос, `#` в начале или управляющие символы |
| `500` | Файл запросов не читается или не записывается |
| `503` | `CONTENT_FACTORY_DELIVERY_TOKEN` не задан |

## Примеры

```bash
curl -f http://127.0.0.1:8000/api/v1/content/queries?language=ru \
  -H "Authorization: Bearer $CONTENT_FACTORY_DELIVERY_TOKEN"

curl -f -X POST http://127.0.0.1:8000/api/v1/content/queries \
  -H "Authorization: Bearer $CONTENT_FACTORY_DELIVERY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"language":"ru","query":"новый запрос"}'
```
